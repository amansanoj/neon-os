# Firmware reliability audit

This review covers every original project source/document and the new release/update code. Dependencies remain pinned, not represented as fully audited. The current implementation has host tests and an ESP32 compile; runtime availability, RF range and flash/bootloader behavior require the hardware acceptance procedure in OTA.md.

| File / subsystem | Finding and action |
| --- | --- |
| `neon-os.ino` | Added main-task watchdog, BLE worker heartbeat supervision, bounded I²C waits, version/build identity, deferred state saves, update health gate and controlled reboot flush. LED updates run at 50 Hz rather than every loop. Memory diagnostics run once a minute. Main loop continues HomeSpan polling; no TLS/download work runs in it. |
| `ble-bridge.h` | Replaced signed absolute deadlines with unsigned elapsed scheduling, including while idle. Avoids stale write deadlines suppressing commands after ~25 days. Kept a one-item latest-state queue and bounded command rate, retry cap and remembered address type. Reuses service discovery on normal reconnects, refreshes after failures. Disconnect callback only stores atomic flags; logging happens in worker context. Worker yields even under continuous input. RSSI logging reduced to once a minute. |
| `homekit-light.h` | Removed immediate per-characteristic flash persistence and per-slider debug output. Added finite/range validation before state mutation. Local controls and notifications remain on the main task. Preserves accessory, service and characteristic ordering for pairing compatibility. |
| `colors.h` | Reviewed constant-time preset/HSV work. Added finite-input fallback and a compile-time uniqueness assertion to prevent another duplicate-preset cycle trap. Exact preset RGB values remain preserved. |
| `interface.h` | Keeps a bounded render snapshot: no framebuffer/I²C transfer while visual state is unchanged. Still updates after state changes while asleep and on wake/rotation. Retains bounded gesture counting, debouncing, long-hold cancellation, RGB text limits and rollover-safe button intervals. Preference write failures are reported. |
| `config.h` | Centralized bounded timing values; updated screen refresh cap and sparse link diagnostics. Pin map and user light address are preserved. |
| `persisted-state.h` | Versioned, validated 14-byte NVS blob instead of padded C++ struct storage. Five-second settling and one-minute minimum save interval, no writes for unchanged state, retry after failures. Explicit read-only migration of old HomeSpan CHAR keys and preset RGB, leaving pairing/old keys in place. Forced latest-state save before OTA reboot. |
| `runtime-policy.h` | Shared unsigned elapsed arithmetic and deferred-save policy; native tests cover wraparound, settling and rate limits. No ever-growing collections or periodic allocations. |
| `ota-updater.cpp` | HomeSpan-independent bounded outbound HTTPS worker; mandatory TLS verification, signed exact metadata, strict target/channel/version/size/URL validation, inactive-slot-only writes, bounded HTTPS redirect handling for GitHub assets, actual flash SHA-256/identity check, SDK image validation before boot switch, pending journal, failed-release quarantine and bounded trial. | `ota-policy.h`, `firmware-version.h` | Explicit release contract and fixed limits. Sequence is separate from human-readable version and must increase for every newly approved binary. |

| `partitions.csv` | Two 0x1F0000 application slots, existing NVS and OTA-data offsets, crash-dump partition, no filesystem. Maximum app space while retaining two slots and diagnostic storage in this selected layout. |

## Remaining operational limits

- Final configured image size must be checked on every release. There is limited remaining flash space on this 4 MB board. Choose an 8/16 MB replacement before dropping the second slot if future features no longer fit.
- Runtime TLS and radio coexistence peak memory cannot be established from the linker report. OTA defers when free heap/largest block is too small, and allocation/network failures leave the current image selected. Test under real HomeKit/BLE traffic; TLS memory thresholds are initial conservative guards, not measured guarantees.
- Soft watchdog recovery and two slots cannot replace reliable power, sound wiring, flash integrity and physical programming access. The solderless breadboard remains a mechanical reliability risk for permanent unattended use.
- HomeSpan still owns its necessary Wi-Fi/pairing NVS data and its own library allocations. This audit removes application slider-driven commits, not all dependency flash writes or all possible dependency defects.
- Avoiding framebuffer transfers does not prevent static OLED pixel wear. Use the existing sleep gesture when a continuously visible panel is unnecessary.
- OLED write acknowledgements are not exposed by Adafruit's framebuffer `display()` API. Timeouts bound a failed bus, but an OLED that silently resets while cached state is unchanged may need a device restart or a subsequent state change. A future panel-reinitialization strategy needs hardware validation.
- State persistence intentionally trades recent-state durability for reduced flash wear. Normal power loss may lose changes within the settling/rate-limit window; pairing is independent.
- OTA signature verification is software-enforced. Secure Boot, flash encryption, eFuse security-version policy and manufacturing provisioning remain a separate hardware-security project. No security fuses are changed here.
- The signing public key and an approved stable GitHub release must be supplied before deployment. A configured example/test profile is not ready for mounting or production flashing.
